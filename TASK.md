# Тестовое задание: Фронтенд-разработчик (Vue 3)

## Цель

Разработать небольшое SPA-приложение «Трекер задач» с авторизацией и CRUD-операциями, используя стек, указанный в вакансии: **Vue 3 (Composition API), Vite, Pinia, Axios, Vue Router, Tailwind CSS**.

Ожидаемое время выполнения: **4–8 часов**. Дедлайн: **3–5 дней** с момента получения задания (сообщите, если нужно больше времени).

---

## Подготовка mock-backend

Полноценный backend писать не нужно — используем `json-server` с плагином `json-server-auth`, который даёт настоящую JWT-авторизацию.

1. Создайте отдельную папку и установите зависимости:

   ```bash
   mkdir mock-api && cd mock-api
   npm init -y
   npm i json-server json-server-auth
   ```

2. Создайте файл `db.json`:

   ```json
   {
     "tasks": [
       {
         "id": 1,
         "title": "Настроить окружение",
         "description": "Установить зависимости проекта",
         "status": "todo",
         "priority": "medium",
         "createdAt": "2026-07-01T10:00:00.000Z"
       },
       {
         "id": 2,
         "title": "Сверстать страницу логина",
         "description": "Форма email + пароль",
         "status": "in-progress",
         "priority": "high",
         "createdAt": "2026-07-02T09:30:00.000Z"
       },
       {
         "id": 3,
         "title": "Настроить Pinia store",
         "description": "authStore и tasksStore",
         "status": "done",
         "priority": "high",
         "createdAt": "2026-07-03T14:00:00.000Z"
       },
       {
         "id": 4,
         "title": "Написать README",
         "description": "Инструкция по запуску",
         "status": "todo",
         "priority": "low",
         "createdAt": "2026-07-04T11:15:00.000Z"
       }
     ],
     "users": []
   }
   ```

3. Добавьте скрипт в `package.json`:

   ```json
   "scripts": { "server": "json-server-auth db.json --port 3001" }
   ```

4. Запустите: `npm run server`.

5. Заведите тестового пользователя:
   ```bash
   curl -X POST http://localhost:3001/register -H "Content-Type: application/json" -d "{\"email\":\"test@test.com\",\"password\":\"12345678\"}"
   ```
   В ответе придёт `accessToken` — это JWT, который выдаётся также при `POST /login`.

Все остальные эндпоинты (`/tasks`, `/tasks/:id` и т.д.) по умолчанию защищены — требуют заголовок `Authorization: Bearer <accessToken>`. Без токена сервер вернёт `401`.

Документация плагина: https://github.com/jeremyben/json-server-auth (если нужны детали — ссылка предоставлена для справки, изучать не обязательно, поведения в п.5 достаточно).

## Функциональные требования к приложению

### 1. Авторизация

- Экран логина (email + пароль) — `POST /login` к mock-api.
- Полученный `accessToken` сохраняется и используется для всех последующих запросов.
- Токен переживает перезагрузку страницы (пользователь остаётся авторизованным после F5).
- Кнопка «Выйти» — очищает токен и редиректит на логин.
- Роут `/tasks` доступен только авторизованным пользователям; `/login` — только неавторизованным (редирект, если уже залогинен).

### 2. Список задач

- Загрузка списка задач через `GET /tasks`.
- Отображение: название, описание, статус, приоритет, дата создания.
- Фильтр по статусу (`todo` / `in-progress` / `done`).
- Поиск по названию (по вводу, без необходимости нажимать кнопку).
- Состояния: загрузка (спиннер/скелетон), ошибка (с возможностью повторить запрос), пустой список.

### 3. CRUD-операции

- Создание новой задачи (форма или модальное окно) — `POST /tasks`.
- Редактирование задачи — `PUT`/`PATCH /tasks/:id`.
- Удаление задачи с подтверждением — `DELETE /tasks/:id`.
- Быстрое изменение статуса задачи (например, через select или кнопки) — `PATCH /tasks/:id`.

### 4. Обработка ошибок сети/API

- Если сервер вернул `401` — пользователь разлогинивается и перенаправляется на `/login`.
- Прочие ошибки API не должны «молча» проглатываться — показывайте пользователю уведомление/сообщение об ошибке.

## Технические требования

- **Vue 3** — только Composition API (`<script setup>` приветствуется).
- **Vite** — конфигурация проекта, переменные окружения через `import.meta.env` (адрес API не хардкодить, вынести в `.env`).
- **Pinia** — минимум два store: для авторизации и для задач. Компоненты не должны напрямую делать HTTP-запросы в обход store/сервисного слоя.
- **Axios** — единый настроенный инстанс (`baseURL`, интерсепторы для подстановки токена и обработки `401`).
- **Vue Router** — с навигационными guard'ами для защищённых и «гостевых» маршрутов.
- **Tailwind CSS** — вся вёрстка, адаптивность на базовом уровне (не должно ломаться на мобильном экране).

## Необязательные бонусы (плюс к оценке, не обязательны)

- TypeScript.
- Unit-тесты (Vitest) для store и/или ключевого компонента.
- Composable-функции для переиспользуемой логики (например, `useTasks`, `useDebouncedSearch`).
- WebSocket-заглушка/эмуляция realtime-обновления списка задач (можно ограничиться описанием подхода в README, если нет времени на реализацию).
- Обработка истечения JWT (токен в json-server-auth живёт ограниченное время) — например, аккуратный логаут с уведомлением вместо «зависшего» UI.
